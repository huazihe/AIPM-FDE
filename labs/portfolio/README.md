# 本地项目作品页实验

用自己的 AI 助手起草结构化项目说明，把结果放入一个无需推理的页面。通过这个最小产品，体验“Agent 负责理解和生成，工具负责承载、校验和呈现”的分工。

## 使用

1. 下载完整仓库，在浏览器中直接打开本地 `labs/portfolio/index.html`。GitHub 的文件页只展示源码，不会执行 HTML。
2. 页面默认显示 [example.json](example.json) 中的合成示例。
3. 让 AI 按下列字段起草自己的 JSON，人工核对后保存到私有工作区。
4. 点击“导入 JSON”，选择文件。错误结构会显示提示，原有内容保留；“恢复示例”回到初始内容。

不需要 Node.js、服务器、模型 API Key 或第三方账号。页面不联网、不上传、不持久保存导入内容，也不会自动发布。重新打开页面会回到示例。

## 字段约定

| 字段 | 类型 | 含义 |
|---|---|---|
| version | 数字，固定为 1 | 本实验的数据结构版本 |
| title、summary | 文本 | 项目名称和摘要 |
| status | 文本 | 教学示例、探索中、已完成离线验证等实际状态 |
| problem、approach | 文本 | 业务问题和处理方法 |
| evidence | 数组 | 每项包含 claim、source、kind 三个文本字段 |
| limitations、next_steps | 文本数组 | 未验证边界和下一动作 |

每个文本最多 2000 字符，每个列表最多 20 项，文件不超过 1 MiB。页面检查结构与长度，不会替你证明证据真伪、因果关系或客户授权。

可给 AI 的请求：

```text
按 example.json 的字段，整理这份已获授权的项目材料。
保留真实项目状态；将每项主张绑定来源，未证实的内容写进 limitations。
只输出 JSON 草稿，不上传、不发布。缺少信息时注明未知，不编造业绩。
```

## 验收

核对标题与状态、主张与来源是否对应，未验证事项是否保留。再导入一份缺少 `version` 的 JSON，确认页面拒绝；导入包含 HTML 标签的文本，确认它只显示为文字、不会执行。

完成后回到 [AI Native 实操课](../../references/ai-native/03-portfolio-lab.md)。如果要把作品真正发布到外部，需要单独确定内容范围、隐私、存储及发布授权；本实验只做本地展示。
