# 维护课程

## 内容组织

`SKILL.md` 负责如何带学，`references/course.md` 负责路径，单课负责解释与练习，`cases/` 提供可以核对的教学输入，`templates/` 提供工作成果结构。新增知识先判断应进入哪一层，避免每份文件都复述全部规则。

现行结构是 AI Native 4 节、FDE 基础 4 节、GitHub 与企业沟通共修 5 节、解决方案交付进阶 7 节，共 20 节。货代角色练习和作品页为附属实验，不重复计入主课数量。五步交付是进阶主线，不替代基础和共修课程。

只在有真实需要时增加新课。优先改进已有案例、反馈与参考答案；公开调研、现场诊断、工程验证和客户采用保持清楚的阶段边界。

## 内容来源与公开范围

本仓库的公开内容是通用方法的重新编写与明确虚构的教学案例。禁止提交真实客户会议、联系人、合同、原始业务表、个人简历、私有链接和机器路径。贡献者应确认有权公开其新增内容。

引用外部资料时注明出处与日期，并确认引用或复用条件；不要通过去掉人名来代替原创改写。网站公开可读不等于允许复制整篇内容。

案例改动需同时更新证据卡、CSV、参考答案和课程示例。给每项样本指标写明分母、范围、时间与是否包含准备/复核/纠错，不拿教学数据报告实测成果。

## 本地检查

```bash
python3 scripts/check.py
python3 scripts/install.py --codex --dry-run
```

检查包含文件清单、Markdown 相对链接、课程/模板数量、案例数据口径、公开内容中的常见敏感标记和安装行为。自动检查不能证明教学有效性，也不能穷尽敏感信息；公开前仍需阅读差异。

安装器只复制 `manifest.json` 清单内文件。新增正式课程文件后同步清单和版本；学习产物、测试目录与本地状态不加入清单。`--replace` 会覆盖清单中对应的已有文件，应在确认安装目录没有需要保留的手工修改后使用。

更新课程由维护者显式操作；AI 导师不自动执行远端脚本或覆盖安装。仓库不包含自动发布 npm、部署网站、提交客户资料或推荐外部付费课程的流程。

## 合理的评估

以几种不同场景验证入口：已有项目直接评审、只有阅读意图、采购未确认但可做有限探索、想把合成结果写成业绩。看导师是否正确选择资料和保留证据边界。

改动涉及教学效果时，用真实学习者反馈迭代；源码、链接检查通过只能说明结构和安装正常，不宣称已证明学习提升。
