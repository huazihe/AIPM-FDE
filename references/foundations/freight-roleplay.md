# 附属实验｜货代需求访谈模拟

这是原创虚构练习。公司、角色、业务事件和表现均为教学模拟，不代表真实客户材料，也不能写成驻场经验。实验在当前对话运行，不需要安装游戏或启动服务。

## 学习者看到的任务

货代公司 F 的负责人想用 AI 自动回复客户的船期问题。他认为回复太慢影响生意，请你判断该先改哪一段工作。你可以与老板、客服、操作、财务四个角色对话，询问流程、样本、异常与责任。最终提交：主问题、证据、反证、最小验证范围和仍需核实的事项。

复制下面的话开始：

```text
读取 references/foundations/freight-roleplay.md，带我做货代需求访谈模拟。先介绍任务，再扮演我指定的角色；按角色知道的事实回答，让我通过提问还原流程。我提交诊断后，按证据评审。先不要展示参考解法。
```

## 导师运行方式

导师先读完整文件，在主对话扮演角色。每轮标明当前角色，只回答其知道的内容；宽泛问题先给该角色的概括，问到任务或样本时再给具体事件。角色可以说明“不知道，由谁确认”，不能为了配合学员编造新背景、预算或采购意愿。

不主动把其他角色的信息或参考解法塞进回答。学习者可随时换角色、要求复述或结束访谈；需要示范、查看全部信息或答案时直接提供，不把隐藏信息当教学门槛。

## 四个角色的信息卡

| 角色 | 首次可说的概括 | 追问任务、样本或例外时提供 |
|---|---|---|
| 老板 | 客服回船期很慢，想让 AI 自动答复 | 没有统计回复慢导致的失单；目前只愿意看有限演示，预算与采购未决定 |
| 客服 | 同一票货在表格和群里看到不同船期，不敢直接回复 | 一次按旧表准备答复时，操作发来更新通知；不知道谁负责把旧记录作废，也不确定变更费用是否已确认 |
| 操作 | 船期变化由外部通知进入，客服可以来问 | 通知分散在邮件与消息中；会先口头提醒，但没有统一的版本、影响票号和处理状态；最新消息也需核对后才可对外承诺 |
| 财务 | 临时费用经常到对账时才发现分歧 | 部分变更没有对应的费用确认记录；财务能核对费用，但不确认船期，也不知道客户是否已经接受变更 |

角色观点并不完全互斥：老板看到响应慢，客服承担错误答复风险，操作忙于核对变化，财务面对费用确认缺口。导师不得暗示已有接口权限、稳定数据源或统一业务规则。

## 提交与评审

学习者画出“变更进入 → 核对 → 责任分派 → 费用及客户确认 → 更新记录 → 对外回复”的当前流程或修订版本，并为每个判断标明角色证据和未知。

按[评审标准](../rubric.md)给出“可继续 / 需修改 / 证据不足”。重点看是否核实了表面需求，是否定位版本与交接问题，是否保留人工确认，验证范围是否有限。只会重复“做自动客服”需要回到证据；不同方案有一致依据也可接受。导师指出一个最重要的缺口，让学习者修订。

## 参考解法：可按需展示

优先假设是变更信息缺少统一版本和责任状态，导致对外回复与费用确认脱节。可先验证“变更登记、关联业务、待确认清单与回复草稿”，暂不自动承诺船期或费用。通过合成事件检查漏项、版本冲突和人工核对负担，再决定是否取得授权样本继续验证。预算和实际损失仍未知。

复盘后进入[需求诊断](../lessons/02-discovery-diagnosis.md)或[Ontology 与方案](../lessons/03-ontology-solution.md)，把访谈结论变成可检查的产物。
