# FDE 基础 03｜能力诊断：让作品支持判断

本课帮助学习者找出当前最值得补的一项能力。诊断面向具体任务和已有证据，不生成缺乏依据的百分制分数，也不凭岗位名称、学校或表达风格判断职业潜力。

## 从作品或任务叙述开始

可以带一份调研简报、业务流程图、原型、评测记录或交付复盘，也可以口述一次项目。无需提交简历。涉及真实项目时，只使用有权用于本次讨论的材料，去除不必要的身份信息；个人诊断和客户原文留在本地学习记录，不进入公开仓库。

先弄清作品的目标、范围、本人贡献、协作支持和实际结果。团队做过的事不自动等于本人独立完成；演示成功也不自动证明具备正式运行能力。缺乏产物时可通过一次小练习补证据，不必先证明自己“配得上”学习。

## 七个观察维度

| 维度 | 可以观察的行为与产物 |
|---|---|
| 业务理解 | 能还原任务与交接，解释问题的后果和优先级 |
| 沟通 | 能区分角色诉求、复述确认、处理分歧和未知 |
| 建模 | 能明确对象、字段、关系、规则、例外与权限 |
| 构建 | 能形成可运行的有限流程，并解释技术依赖与失败路径 |
| 评测 | 能定义基线、样本、口径，区分技术表现与业务结果 |
| 推进 | 能安排责任、验证节点、范围变更和工程交接 |
| 复用 | 能从一次项目提炼适用条件明确、可被他人使用的方法 |

诊断不要求每项都有相同深度。先按目标路线确定近期最重要的维度，再判断现有证据是否够用。没有观察到的能力记为未评审，不能直接写成不会。

## 怎样通过访谈补证据

针对一个真实片段追问：“你当时根据什么作决定？有没有相反信息？你负责哪部分？结果如何确认？如果重做会改变什么？”每次围绕一个缺口展开，避免连环盘问背景。

例如，学习者展示了一份能运行的自动提取工具。它可以支持部分构建能力，但仍需查看缺字段时的处理、测试样本和人工复核负担，才能判断评测与交付能力。如果工具由别人完成，应进一步确认本人做了哪些需求、规则或验收工作。

## 把诊断变成练习处方

采用“可继续 / 需修改 / 证据不足”的[评审口径](../rubric.md)，每项结论附作品位置、判断依据和最小补证动作。不要把七个维度平均成一个貌似科学的总分，也不要根据一次练习承诺录用、收入或岗位适配。

若需求判断有依据，但规则仍靠“按经验处理”，下一步可以只补一条完整业务规则；若原型可用却没有基线，就补一次范围一致的比较。练习应当改变一个具体判断，而不是生成一张更漂亮的能力雷达图。

## 练习与验收

选择一份作品，按七维填写“证据、当前结论、尚缺信息、下一动作”，再选一项最影响当前目标的缺口完成修订。没有作品时，用[制造业案例](../../cases/manufacturing-quote/brief.md)完成一份诊断卡或业务模型；需要练现场提问时，进入[货代需求访谈模拟](freight-roleplay.md)。模拟表现只作为练习证据，不等于真实客户经历。

验收看：是否区分个人与团队贡献；结论能否回指产物；未知是否被误写成能力不足；建议是否能直接执行。交付一页能力证据卡和一项修订。业务缺口进入[需求诊断](../lessons/02-discovery-diagnosis.md)，规则缺口进入[Ontology 与方案](../lessons/03-ontology-solution.md)，验证缺口进入[POC 课程](../lessons/04-poc-delivery.md)。
