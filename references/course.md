# 学习路线

学习目标是把 AI PM 的产品能力接到具体企业的业务结果上。课程从一个完整的虚构项目进入，以产物和判断为线索学习。

2. [AI 工作区与协作](ai-native/02-workspace-collaboration.md)：文件、权限、版本、工具和验收怎样改变工作。
3. [本地项目作品页实验](ai-native/03-portfolio-lab.md)：把项目证据变成可审阅的结构化成果。

## 按起点选择路径

**想理解 AI Native 产品**：AI Native 01 → 02 → 03 → 04；动手优先者可先做 03，再回补分工与架构。不会 GitHub 时接入共修。

**想判断如何做 FDE**：基础 01 → 02 → 03，职业选择需要当前市场证据时读 04。能力诊断结果指向 AI Native 构建、沟通共修或五步进阶。

**已有 AI PM 基础，完成交付练习**：进阶 00 → 01 → 02 → 03 → 04 → 05 → 06。用 [制造企业 M](../cases/manufacturing-quote/brief.md) 完成五份模板，所有结论引用案例证据。角色定位不清补基础 01/02，准备见老板接入企业沟通。

**现有项目补课**：已有调研资料但问题不清，从 02 开始；需求明确但 AI 反复误解字段，从 03 开始；演示成功但无法验收，从 04 开始；已部署但没人用，从 05 开始。上游关键信息缺失时局部回补，不重新跑整条流程。

**成果评审**：带一份脱敏作品，先用 [评审标准](rubric.md) 定位缺口，再读对应课。可以直接完成综合项目；只有证据支持的部分记为已验证。

## 学习循环

一次学习完成一个有价值的判断：

1. 解释：这一步要决定什么，为什么影响后续交付。
2. 示范：沿案例把证据变成结论，展示推断边界。
3. 实践：填一份能给下一位同事使用的产物。
4. 反馈：指明缺的是数据、定义、决策还是表达。
5. 迁移：换一个业务场景，说明哪些框架可复用、哪些规则必须重访谈。

时间按背景与产物复杂度调整，不承诺固定天数掌握 FDE。阅读、完成练习、通过教学评审和客户真实采用是不同状态。

## 你不需要先做的事

不要求重新学习所有 AI 和 GitHub 基础，不要求先参加能力考试，不要求先配置外部产品或上传简历。真实练习需要的能力在对应课程内补齐。
