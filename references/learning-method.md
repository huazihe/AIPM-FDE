# 学习方法：用作品检验判断，再迁移到新场景

已有 AI 产品经理基础的人，常见缺口是无法把熟悉的方法接到客户现场。学习时以一次业务判断为单位，把新知识落到产物上，再用反馈修正。

## 1. 用已有作品定位起点

先看学习者手里的调研、PRD、流程图、原型或评测报告：它能支持什么决定，下一位同事还要猜什么？如果需求已明确，直接进入业务建模；如果模型表现不错但用户不用，优先学采用与流程调整。职业头衔不能替代作品证据，也不需要先做漫长背景问卷。

只想听课的人可以直接看完整示范。没有作品时，用仓库案例作为共同输入，避免因没有客户资源而无法开始。

## 2. 先看一次判断如何形成

导师展示的不只是最终表格，还要解释一条结论的形成过程：证据说了什么，有什么反证，为什么选择这条业务切片，暂时放弃什么。把“输入 → 判断 → 产物 → 下一决策”讲出来。

示范一条“资料版本冲突”的诊断后，再请学习者自行处理“价格有效期”。用相近但不相同的问题检查理解，避免只照抄措辞。

## 3. 逐步减少支架

第一次提供完整模板和示范；第二次保留字段，减少示范；迁移练习只给业务材料和完成标准。减少帮助应依据学习者的表现与意愿，不按固定次数机械执行。

用户要求答案时可以直接给；记录其当前状态为阅读或跟练，不将其写成独立完成。用户已有成熟作品时，可以直接进入评审。

## 4. 围绕最薄弱的决定练习

反馈要定位到具体判断。如果问题是“把采访中的一句话当成全公司频率”，练习就是补采样方案和证据范围；不要求重写整份文档。如果公式概念混淆，先用一个可手算的例子验证，再恢复方案设计。

对每次修改保留“原判断、反馈、新判断、仍未知”。这样可以看见能力变化，而不是只积累越来越长的资料。

## 5. 让五份成果相互约束

同一案例贯穿五步，是为了暴露阶段之间的错位。需求说减少返工，方案却只优化界面，评测又只看输出速度，就无法形成连贯交付。评审时沿一条证据逐步追踪到方案、指标和回流项。

学完后可以自愿做一次不看答案的复述：当前最重要的业务问题是什么，什么证据会推翻判断，下一步该找谁确认？无法回答时回到相应产物补齐，而不是反复背术语。

## 6. 用迁移区分框架与业务规则

在[报告审核挑战](../cases/transfer-challenge.md)中复用五步结构，重新定义对象、错误成本、审批与指标。可迁移的是判断方式；不能直接迁移的是客户的字段、价格规则、阈值和组织权限。

完成练习后，再在有授权的真实项目中验证。教学评审、真实工作表现与业务结果分别记录。仓库提供的是可操作的学习设计，其效果仍需要通过实际学习者反馈不断改进。
