# AI Native 02｜把一次对话变成可交接的工作

本课讨论个人 AI 工作区怎样改变工作组织。关键不在聊天框多了几个按钮，而在助手能够在获准范围内读取材料、使用工具、生成文件，并让人检查结果。具体能力依赖所用工具、连接方式与权限，不假定所有产品都能执行相同操作。

## 从回答问题到完成任务

一次普通问答可能止于文字建议。完成任务则需要输入、目标、约束和验收：用哪些材料，为谁产出什么，哪些事实不能补猜，什么结果才算可交付。助手执行后留下文件、差异或检查记录，下一位同事能据此继续，而不必重读全部聊天。

因此，工作区要同时容纳“正在做什么”和“结果依据什么”。任务说明写清目标，来源材料保留原意，输出文件有稳定位置，未解决问题有状态。目录数量不重要，重要的是别人能分辨输入、草稿和当前有效成果。

## 五项基本约定

| 约定 | 需要讲清的内容 |
|---|---|
| 工具 | 助手实际能读取、计算或修改什么；不可用时怎样处理 |
| 文件 | 输入与输出在哪里，哪份是当前有效版本 |
| 权限 | 哪些操作已获授权，谁批准外发、部署或写入系统 |
| 版本 | 改了什么，依据什么，如何保留旧判断及变更原因 |
| 验收 | 谁检查内容、结构、运行行为和业务效果 |

这些约定不要求每次填一张大表。简单任务可以一句话说清；多人协作、长期任务或高影响操作才需要更完整的记录。

## 示范：整理一份项目作品材料

输入是经过允许使用的项目笔记，目标是生成一份结构化证据卡。先说明只能采用材料支持的事实，贡献不明的地方保留未知；助手整理草稿，用户核对问题、行动、结果和本人责任，再保存确认版本。

如果用户后来纠正“只是测试，没有客户采用”，应同步修改证据卡、页面和摘要，而不只改聊天中的一句话。一个信息有多种呈现时，要指定一个主要维护来源，其他文件根据它更新，减少互相矛盾的副本。

## 让交接小而完整

任务中断前，保存当前成果位置、已完成检查、未解决问题与下一动作。继续工作时先回读当前文件，再采用历史记录；聊天记忆只能帮助定位，不能替代当前状态。

版本也不等于已经验收。文件已保存只说明内容落盘，脚本成功只说明程序完成了对应操作。作品页还要检查文字是否忠实、字段是否遗漏；客户项目还要核对真实使用。检查力度由交付风险决定。

## 练习与判断标准

为“从项目笔记生成作品页”写一份任务说明，包含允许使用的输入、输出文件、事实边界、版本约定和完成标准。请助手起草证据卡，然后人为加入一条状态纠正，观察所有相关成果是否同步更新。

交付任务说明、确认后的文件和一段交接摘要。判断标准是：另一位协作者能找到有效版本，能追溯一条关键陈述，也知道哪些内容尚未验证。若必须靠你口头解释才敢使用，继续补齐缺失的约定。下一课进入[本地作品页实验](03-portfolio-lab.md)。
