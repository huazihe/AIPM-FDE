# 企业 M：参考判断与计算

> 本页解释虚构案例的一种解法。所有记录均为手工合成；没有实际模型测试、客户采购、生产部署或业务收益。允许提出不同方案，但必须保持证据、范围和数字口径一致。

## 1. 调研与诊断

E01 只支持“按图生产、有多个岗位、已有系统”等背景。询价时效、失败比例和预算仍未知，应在调研简报中列为待访谈问题。不要从企业介绍直接生成“每年可节省多少万元”。

主假设可写为：**询价进入核价之前，版本、字段与价格条件缺少一致校验，造成反复查证和交接返工；先验证带来源的结构化整理及异常分流。** E03—E06 提供支持；反证与未知包括人工复核是否比原流程更费时、是否产生双份录入、缺价等待是否才是主要瓶颈。

| 判断 | 当前结论 | 下一证据动作 |
|---|---|---|
| 痛点是否成立 | 案例描述中有具体任务、角色和返工原因，支持局部问题；全公司频率未知 | 分任务类型记录实际发生量、操作时间和失败样本 |
| 是否值得优先解决 | 小范围验证有理由，尚不能证明全流程投入收益 | 对比总人工成本、质量底线、采用负担与其他瓶颈 |
| 是否近期可采购 | 未知；E08 没有批准预算、决策人或流程证据 | 由发起人安排决策人与财务对齐验证结果、投入和采购条件 |

有边界的离线 POC 可以按 E08/E11 的教学设定继续。商机资格、试验授权和生产上线是不同判断；任一状态不能替代另外两项。

## 2. 最小业务模型

建议对象至少包含：询价单、询价明细、图纸版本、价格记录、成本估算、报价版本、审批决定。询价单包含多条明细；明细引用被确认的图纸版本；成本估算引用有效价格和规则版本；报价版本引用成本估算；审批决定绑定具体报价版本。

两个最容易漏的字段是“来源定位”和“规则/数据版本”。只有最终数值，没有来源与版本，人工无法高效核查，也难以解释变更。

字段不能只写名称：`unit_mass` 还要定义单件含义、数值类型、单位、来源和空值处理；`drawing_revision` 与 `quote_revision` 必须分开。审批后改变关键输入应创建新报价版本并重新审批，见 R06。

若教学总成本 C = 80，目标毛利率 m = 20%，简化报价为 80 ÷ 0.8 = 100；直接算 80 × 1.2 = 96 使用的是成本加成率，得到的毛利率为 16.7%，概念不同。这些数字仅为公式说明。

## 3. 首轮方案边界

AI 可以从附件中提出字段候选、标出冲突并引用来源。确定性规则负责单位换算、价格有效性检查、金额计算、版本失效和审批路由。业务与技术人员确认冲突和例外；授权负责人审批；人负责对外发送。

本轮不自动定价、不自动发送、不替换现有业务系统。U01“老客户小改动按上次价格”缺少适用条件，先留在待核规则表。方案的价值是把人工审阅放在有依据、可解释的位置，不能以减少审核次数本身作为成功。

## 4. 样本计算

从 CSV 逐列相加，得到：

| 指标 | 计算 | 结果 |
|---|---|---|
| 基线人工总时间 | 10 条 `baseline_active_min` 之和 | 290 分钟 |
| 试点准备时间 | `pilot_prepare_min` 之和 | 47 分钟 |
| 试点复核时间 | `pilot_review_min` 之和 | 74 分钟 |
| 试点纠错时间 | `pilot_correction_min` 之和 | 17 分钟 |
| 试点操作时间 | `pilot_operations_min` 之和 | 10 分钟 |
| 试点重复任务人工时间 | 47 + 74 + 17 + 10 | 148 分钟 |
| 重复任务净节时 | 290 − 148 | 142 分钟 |
| 重复任务净节时比例 | 142 ÷ 290 | 49.0% |
| 含一次性投入的首批时间 | 148 + 60 | 208 分钟 |
| 首批净节时及比例 | 290 − 208；82 ÷ 290 | 82 分钟；28.3% |
| 首次字段准确率 | 95 ÷ 100 | 95% |
| 案例中的异常分流 | 6 个应分流样本均标为已分流 | 6/6，仅为合成标签 |

每单平均基线为 29 分钟，试点重复作业为 14.8 分钟。**不能只用 47 分钟“准备时间”与 290 分钟比较**，那会漏掉复核、纠错和工具操作；也不能在 290 分钟上重复增加基线返工。

可以用 Python 标准库复算，无需安装依赖：

```python
import csv
from pathlib import Path

rows = list(csv.DictReader(Path("cases/manufacturing-quote/sample-data.csv").open(encoding="utf-8")))
baseline = sum(int(r["baseline_active_min"]) for r in rows)
parts = ["pilot_prepare_min", "pilot_review_min", "pilot_correction_min", "pilot_operations_min"]
pilot = sum(sum(int(r[k]) for k in parts) for r in rows)
print({"baseline": baseline, "pilot": pilot, "net_saved": baseline - pilot,
       "first_batch_saved": baseline - pilot - 60})
```

技术与业务之间的链条可写为：字段候选及来源定位 → 首次正确率、异常漏检率、人工复核成本 → 每单总人工时间、返工、按时完成情况 → 在真实持续使用后，再评估产能、响应周期或经营收益。中间任何环节未验证，都不能跳到最后一个结果。

本样本量小且完全合成，没有自然业务分布、持续采用数据和真实成本，所以不能外推“年度省钱”“提升成交率”或“可以裁减多少人”。在真实试验中，还应使用未参与规则设计的样本、分类型报告、保留失败记录，并明确配对方法和版本。

## 5. 验收与交接判断

可为下一轮提出教学目标：关键输入缺失时必须阻断；已审批内容发生变化后旧审批失效；所有对外内容可追溯；比较全部人工作业时间；异常能回退人工流程。这些是**待验证目标**，不能因为答案写了规则就算通过。

离线样本验证与生产交付分开记录。生产交接仍需负责人确认访问权限、数据备份、日志、告警、回滚步骤及支持边界。原型能显示页面或导出结果，不证明这些项目已实现。

## 6. 采用与产品回流

E10 只有有限试用意愿，不能写“已规模化采用”。先消除双份填报，确认岗位责任，再在授权条件下观察实际使用量、合格任务覆盖、退出原因和净节时。经理满意不代替一线可用。

F01 归为 Bug；F02 归为新需求；F03 归为使用障碍；F04 归为效果问题。四类分别进入修复、需求判断、流程调整和评估补证。痛点库保存问题、场景、影响和证据状态；方案库保存适用条件、输入输出、规则、验收及失败边界。

“字段提取附来源、版本变更触发复核”可作为候选复用能力。“20% 毛利阈值”和具体定价公式属于本案例约定，不能一并搬给下一位客户。共性程度、业务价值、采购意愿、预算与研发投入需要共同评审，不能只凭出现次数自动排期。
